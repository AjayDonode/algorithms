🗺️ Dijkstra's Algorithm

Find the shortest path in a weighted graph — visually, step by step

Step 0 — The Idea in Plain English
🏙️

You're a GPS

You're at node A and want to reach node F via the shortest route. You don't know the layout — you have to discover it.

🕵️

Always Pick the Cheapest

At every step, explore the unvisited node with the smallest known distance. Never revisit a confirmed node.

✏️

Keep a Scoreboard

Maintain a table of "best known distance to every node". Update it whenever you find a shorter route.

✅

Lock-In When Sure

Once you pick a node as "cheapest unvisited", that distance is final. No shorter path can exist (non-negative weights).

Step 2 — How It Works (Pseudocode)
Pseudocode
1function dijkstra(graph, source):
2 dist[source] = 0 // distance to source is zero
3 dist[every other node] = ∞ // all others unknown → infinity
4 prev[every node] = null // track how we reached each node
5
6 minHeap = PriorityQueue() // always picks the cheapest node next
7 minHeap.add(source, cost = 0)
8
9 while minHeap is not empty:
10 current = minHeap.poll() // pick cheapest unvisited node
11
12 if current already visited: continue // skip — already confirmed
13 mark current as visited // lock in this distance forever
14
15 for each neighbour of current:
16 newDist = dist[current] + weight(current → neighbour)
17
18 if newDist < dist[neighbour]: // found a shorter path!
19 dist[neighbour] = newDist // ← RELAXATION: update scoreboard
20 prev[neighbour] = current // ← remember how we got here
21 minHeap.add(neighbour, cost = newDist)
22
23 return dist, prev
Step 3 — The Key Concept: Edge Relaxation

The most important operation is called relaxation. Every time you process a node, you ask its neighbours:

// Can I reach neighbour B CHEAPER by going through current node A?
newDist = dist[A] + weight(A→B)

if newDist < dist[B]: ← found a shortcut!
    dist[B] = newDist ← update the scoreboard
    prev[B] = A ← remember how we got here
Before relaxation
dist[A] = 4
weight(A→B) = 3
dist[B] = 12 (old)
After relaxation
newDist = 4+3 = 7
7 < 12 → update!
dist[B] = 7 ✅
Step 4 — Why Always Picking the Minimum Works

This is the key question: "why can't a cheaper path appear later?"

When we pick node X with distance d as the minimum unvisited:

→ Every other unvisited node has distance ≥ d
→ All edge weights are ≥ 0 (non-negative constraint!)
→ Any path to X going through another unvisited node would be ≥ d + 0 = d
→ So d is already the shortest possible — lock it in! ✅

⚠️ This breaks with negative weights — use Bellman-Ford instead.
Step 5 — Complexity & When to Use What
AlgorithmWeightsTimeBest for
BFS Unweighted (all = 1) O(V + E) Grid shortest path, word ladder
Dijkstra Non-negative weights O((V+E) log V) Road maps, network routing
Bellman-Ford Any weights (incl. negative) O(V × E) Currency arbitrage, negative cycles
Floyd-Warshall Any weights O(V³) All-pairs shortest path (small graph)
A* Search Non-negative + heuristic O((V+E) log V) Game pathfinding, GPS with goal

2
3 int[] dist = new int[n];
4 Arrays.fill(dist, Integer.MAX_VALUE); // all distances = ∞
5 dist[src] = 0; // source to itself = 0
6

8 PriorityQueue<int[]> pq = new PriorityQueue<>(
9 Comparator.comparingInt(a -> a[1]));
10 pq.offer(new int[]{src, 0});
11
12 boolean[] visited = new boolean[n];
13
14 while (!pq.isEmpty()) {
15 int[] cur = pq.poll();
16 int node = cur[0];
17 int d = cur[1];
18
19 if (visited[node]) continue; // already confirmed — skip
20 visited[node] = true; // lock in this distance
21
22 for (int[] edge : graph.get(node)) {
23 int nb = edge[0];
24 int w = edge[1];
25
26 if (d + w < dist[nb]) { // ← RELAXATION
27 dist[nb] = d + w; // shorter path found!
28 pq.offer(new int[]{nb, dist[nb]});
29 }
30 }
